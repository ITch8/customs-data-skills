# 外贸静态站规划

把网站做成可抓取的静态 HTML 和可核对的询盘路径。方法来自 [b2b-fast-builder](https://github.com/jackzhang1314/b2b-fast-builder/tree/main/skills/b2b-fast-builder)。

本环境没有 Cloudflare、D1、Resend、Turnstile、R2 或 Tidio 集成，也没有 `$b2b-builder`、`$cloudflare`、`$frontend-design`。需要查官方参数时用 `web_search`。不要把规划写成已经部署，不要创建云资源，不要把密钥写进仓库、对话或前端。

## 何时使用

- 新建或改造没有 CMS 的外贸 B2B 静态站、国家站、小语种站或 SEO 专题站。
- 内容由文件或结构化数据维护，更新后可以重新构建。

需要运营人员在后台实时新增产品、草稿发布或前台编辑时，说明这超出本技能，不要假装用静态构建代替 CMS。

## 不可破坏的边界

1. 每个 SEO 路由必须直接给出完整 HTML。标题、正文、参数、链接和结构化数据不能等浏览器执行 JavaScript 才出现。
2. 只有一个空壳 `index.html`、其余路由都回退到它的客户端 SPA，不能当成 SEO 静态站。
3. 同一事实只保留一处真源，不在多个文件里复制。
4. 询盘先落库，再发邮件。邮件失败不能让询盘消失。本环境只能写出这个状态模型，不能声称已经写入 D1 或发出 Resend。
5. 只有保存成功才能进入独立 `/thank-you/`。写入失败时留在表单并保留输入。感谢页 `noindex`，不进 sitemap，转化事件用询盘编号去重，不传个人身份信息。
6. 媒体模式必须写明。默认 `local`。多站共享或大文件才用对象存储。两种模式不能无规则混用。
7. 客户、认证、产能、交期、案例、效果数字和出口国家必须可核验。占位内容标成待确认，并保持 `noindex`。
8. 对标站只用来研究信息顺序、关键词、页面结构和转化路径，不复制 Logo、文案、摄影或专有设计。
9. 密钥不进前端和仓库。
10. 规划不等于获准上线。部署、切域名、生产写入必须是用户明确要求的范围。
11. 域名、托管、发信和生产仓库默认属于客户自己的账号。
12. 开场只问业务和必要的设计偏好，不先索要全部密钥。
13. 类型检查、lint、测试、构建、路由 HTML、title、canonical 或 sitemap 任一失败，就停止部署。
14. 颜色、字号、间距和宽度使用统一语义变量，不在组件里散落任意色值。
15. 在线聊天不能替代站内询盘。未接通时标明预览，测试替身不能进入生产。

## 工作流

### 1. 确认样板所需信息

先看用户已有资料。缺这些项时再问，并标成待确认，不用假数据补齐：

- 卖什么、卖给谁、目标国家、语言。
- 首版页面和主询盘动作。
- 哪些证据是真的，哪些还没有。

### 2. 写出可确认的契约

用 Markdown 记录，不要求一次填完：

- 业务与目标买家。
- 搜索意图和页面分类依据。分类来自买家任务，不来自老板的图册目录。
- 路由清单、页面模板和主按钮。
- 内容真源、语言策略、SEO 字段从哪来。
- 询盘字段、感谢页。聊天只记录需求。
- 媒体策略，未说明时默认 `local`。

域名、收件人和密钥允许待配置。契约里不存密钥的值。

### 3. 先做可看的样板

优先规划首页、一个分类页、一个产品详情页。说明每页的买家任务、首屏要回答的四件事：卖什么、卖给谁、为什么可信、如何询盘。

样式确认不等于内容确认。用户认可样式后，再收集公司介绍、产品信息和图片。缺资料可以继续排版，但不得带未确认产品和假证据写成可发布版本。

### 4. 静态页面要求

`/products/example/` 应对应 `dist/products/example/index.html`。列表、详情和 metadata 来自同一真源。不要手写大量重复页面，也不要把正文留给浏览器端渲染。

默认技术方向是构建期为每条已知路由生成完整 HTML。若项目已经使用别的合格静态导出，先沿用，不为换框架而重写。

### 5. 询盘状态

每条询盘至少包含：编号、提交去重键、时间、姓名、邮箱、公司、电话、国家、需求、来源 URL、UTM、询盘状态、邮件状态、邮件编号、重试次数、最后错误。

重复提交由去重键拦截。邮件失败但已保存时仍可进入感谢页；未保存则不得跳转。

### 6. 交付

把契约、路由清单和页面说明写成项目文件，并用 `present_artifacts` 交给用户。只有用户明确要求且本环境真的执行过构建或部署时，才写通过；否则列出未运行的检查。
