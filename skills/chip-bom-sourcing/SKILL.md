# 芯片 BOM 与型号寻源

目标是让不同供应商对同一个可验证的需求报价，不猜料号、不混淆兼容性，也不把目录搜索结果当作现货证明。

## 1. 清理需求

逐行保留原始描述，并提取：制造商、完整 MPN/订货后缀、数量与分批计划、需求日期、交付地、应用/工作环境、封装、温度等级、环保/质量要求、包装方式、可接受批次范围、要求的追溯文件和测试标准。标记原文、已确认字段、缺失字段，禁止默默补齐后缀或单位。

若 MPN 不完整或描述只含功能/系列，向买方询问完整型号、原厂链接/数据手册、照片或 BOM 修订版。需要工程判断的引脚兼容、固件、精度、耐压、温度或安全等级问题必须由买方设计/质量责任人确认。

## 2. 核对产品事实

使用 `web_search` 找制造商官网产品页、数据手册、订货信息、PCN/EOL 和官方生命周期信息。记录文档标题、URL、版本/修订号、发布日期（若有）和查询日期。产品存在、规格、包装和生命周期以适用的原厂材料为基准；第三方分销页面只作为线索。

知识库中的内部 BOM、历史订单、客户认可供应商和质量标准按当前权限检索。确认文件对应的客户、产品修订和生效日期；历史报价不能当成当前可售价格。

## 3. 询价字段

把询价表整理为可复制的表格：原始行号、制造商、MPN、数量、交期、目标交付地、质量/追溯要求、允许批次、报价币种与有效期、交货条件、付款条件、原厂包装/标签、产地与原产地证明要求、报价来源及查询日期。

要求供应商逐项确认是否 exact MPN、库存所在地、库存/交期性质（实物、在途、可订）、批次/日期码范围、包装状态、退换条件、可提供文件和文件签发主体。没有书面回复的字段保留为空。

## 4. 比较报价

先确认报价可比：完全相同的 MPN、数量、批次/追溯标准、交期、交付地、币种、贸易术语版本与指定地点、税费/运费口径、付款和保修条件。再标明报价时间、有效期及是否含税/运费；不将不同口径的数字直接排序。运费、税费、汇率或落地成本没有可靠输入时只列计算项，不编造总价。

## 5. 替代料控制

任何不同 MPN、制造商、封装后缀、温度等级或工艺版本均先标记为“候选替代”，不是等同料。附差异清单和对应原厂资料，请买方设计/质量责任人书面批准并完成所需验证前，不得把替代料写成可直接下单或已获客户认可。

## 交付和暂停条件

输出一份“已确认 / 待确认 / 证据 URL / 查询日期 / 风险”表和下一步问题。型号不唯一、报价无法同口径比较、批次追溯缺失或替代未经书面批准时，明确暂停下单准备。
