# 芯片贸易合规与交易关口

这是交易信息整理和合规问题清单，不是分类、法律意见、制裁筛查或放行决定。内贸也要核验合同、产品质量、税票、主体和适用监管要求；跨境还要核对完整物流路线和两端规则。

## 先收集交易事实

- 买卖双方完整法定名称、注册地、实际参与方及其角色。
- 芯片制造商、完整 MPN、技术规格、原产地/来源和现有分类依据。
- 发货地、过境/转运地、目的地、进口商、最终收货人、最终用户及最终用途。
- 数量、金额、币种、交付日期、物流和保险安排、贸易术语及具体指定地点。
- 是否涉及军用/军民两用、高性能计算、加密、航空航天、受管制主体或其他敏感用途；不确定时标未知。
- 需要的发票、装箱单、合同、原产地、产品合格、许可或其他单证及各自责任人。

任一会实质改变适用规则的信息缺失时，先询问，不推断国家、原产地、最终用户或用途。保留客户原始声明并标明尚未独立验证。

## 当前规则核验

1. 用 `web_search` 查询交易涉及司法辖区的政府监管机关、海关/关税查询系统和官方制裁/出口管制页面；记录页面标题、URL、查询日期、适用辖区和仍未回答的问题。
2. 产品分类（例如海关税则编码或出口管制分类）必须基于具体型号技术参数、规则版本、交易方向和法律辖区。不能从“芯片”类别猜编码，也不能仅靠相似料号、旧申报记录或供应商结论确定分类。
3. 核查许可、最终用途/用户限制、转运与再出口限制、受限制主体、原产地、税费、标签和单证要求。名单或规则查询应覆盖交易各方和真实受益/最终用户，且查询时点紧邻交易审核。
4. 适用规则或官方数据库不能访问、信息互相冲突、命中相似名称、分类不明确、最终用途不清或许可条件可能适用时，标为“待合规负责人确认”，暂停承诺、收款/付款或发货等受影响动作。
5. 内部知识库中的旧分类、旧许可证和旧案例只作线索。核对辖区、产品参数、交易日期和负责人批准记录；过期或范围不匹配的内容不能直接复用。

不得指导规避制裁、出口管制、许可证、原产地或申报要求；不得把拆单、改标签、经第三地转运或替换交易主体描述成合规解决方案。

## 输出

生成交易事实表和关口清单，状态仅用“资料齐 / 待补证 / 官方核验完成、待负责人判断 / 暂停”。逐项给出事实来源、查询日期、责任人及下一步。官方来源只能支持其页面实际陈述，最终放行结论由企业合规/法务/报关责任人根据完整交易材料作出。
