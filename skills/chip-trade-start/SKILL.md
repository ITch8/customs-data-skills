# 芯片贸易入门路线

把“想做芯片贸易”转成一组可验证的小步骤。先摸清用户现状，再逐步收敛产品、客户和采购路线；不要求用户一开始就选内贸或外贸，也不替用户承诺采购或投资金额。

## 第一步：盘点起点

先从用户已提供的信息中整理，不重复追问：

- 地区与可覆盖市场：本地、中国境内、跨境或未定。
- 现有资源：电子行业经验、工程/采购联系人、潜在买家、供应商、资金与库存承受度。
- 兴趣产品：已知芯片型号/应用，或汽车、工业、消费电子、通信、计算等应用方向。
- 经营方式偏好：撮合/代理、现货分销、按单采购、库存分销或未定。

最多一次询问 3 个最影响下一步的问题。信息仍不足时，给出带假设的两个候选方向，不要替用户选定高库存路线。

## 第二步：选择一个窄切口

用“应用场景 + 产品族 + 买家类型 + 可验证供货方式”描述候选切口。芯片可先按 MCU、存储器、模拟/电源、逻辑/接口、功率、射频、传感器或分立器件归类；该分类只用于沟通，不代表完整技术分类。

比较候选方向时逐项说明：客户需求证据、目标客户是谁、型号是否容易准确识别、供货与授权状态能否核验、批次和质量文件要求、停产/替代风险、资金占用及合规检查复杂度。没有数据的项目标为待验证，不打分伪装精确结论。

## 第三步：验证需求

选一个低成本验证动作：访谈潜在采购/维修/研发人员，获取脱敏 BOM 或明确型号需求，或检索目标市场公开的产品与渠道信息。记录公司角色、应用、确切 MPN、数量/预测、所需日期、质量文件、目标交付地和证据 URL。不要把单个询价当作稳定市场需求。

易变市场数据、产品生命周期、价格和渠道状态必须用 `web_search` 检索制造商或其他一手官方页面，并写查询日期；找不到官方信息时标“未核实”。企业政策、历史询报价、客户画像或已采购流程才从当前会话有权访问的知识库检索。

## 第四步：跑通一笔小交易的准备流程

1. 先用 `chip-bom-sourcing` 补齐型号、版本、数量、交期和质量要求。
2. 用 `chip-supplier-check` 核验供应链路径、追溯文件和交易主体。
3. 用 `chip-trade-compliance` 检查交易路线、目的地、最终用户/用途和当前合规核验项。
4. 将买方需求发给至少两家可核验的供货来源询价；对比项要同型号、同批次要求、同数量和同贸易条件。
5. 付款、下单、进口/出口申报或向客户承诺前，让授权负责人核对合同、文件、质量责任与合规结论。

不要建议通过囤积难以追溯的热门料号“试水”。对于高价、受控、停产、汽车/航空/医疗等高可靠性应用、或买卖双方名称不一致的交易，先停在调查和人工审核阶段。

## 每次交付

- 当前阶段和已知条件。
- 尚缺的关键事实及为什么影响决策。
- 1–3 个按顺序执行的下一步，每步写出可观察产物。
- 需要实时核实的信息及已查来源/日期。
- 需要工程、质量、法律或合规人员确认的事项。

区分事实、用户陈述、检索证据和假设。资料不足时给可执行的补证动作，不给“可以放心做”一类保证。
