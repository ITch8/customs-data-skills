# 芯片贸易知识库：首批资料与维护规则

这份指南用于建立可检索、能判断适用范围且可淘汰过期内容的业务知识库。它不提供某个料号的当前价格、生命周期、库存、授权或监管结论。

## 按用途分库或分目录

1. **产品与技术**：制造商数据手册、产品选择指南、订货规则、PCN/EOL、可靠性与包装资料。优先保存原厂发布版本。
2. **供货与质量**：授权渠道核查流程、供应商准入、CoC/追溯要求、来料检验、抽样、退换和异常案例。区分公司制度与外部建议。
3. **市场与客户**：目标细分、访谈纪要、脱敏 BOM/RFQ、渠道调研和复盘。明确这是调查样本，不代表总体市场。
4. **交易操作**：询价模板、报价口径、合同/采购/物流/税务/发票/收付款 SOP。按内贸、出口、进口和司法辖区标范围。
5. **法规与合规**：官方规则原文或官方查询结果、内部审核流程、经责任人批准的分类/许可意见。敏感资料设置最小读取范围。

## 每份资料的元数据

文件名或文档首页应能检索到：`source_name`、`source_url`、`publisher`、`document_type`、`published_at`、`retrieved_at`、`reviewed_at`、`review_owner`、`valid_for`（市场/辖区/产品/客户/流程）、`revision`、`status`（current、needs_review、superseded、withdrawn）、`confidentiality`。批次/型号资料另记录完整 MPN、批次/日期码和适用客户/项目。无法取得字段时写“未知”，不要留给模型猜。

入库时尽量保留原文件、版本和 URL；扫描件 OCR 后抽查表格、脚注、料号后缀和法律例外条款。不要把多个版本合并覆盖成一份无版本记录的“最新版”。

## 来源优先级

- 产品规格、PCN/EOL、包装：制造商当前产品页和原始技术文件。
- 授权渠道：制造商面向对应市场的官方授权渠道查询；本地法规：相关政府监管机构与海关官方系统。
- 企业流程、客户要求、历史成交：本企业有权限访问且注明生效范围的文件。
- 分销平台、行业新闻、论坛、供应商宣传：用于发现线索和交叉检查，不单独支撑当前生命周期、真实库存、授权或法律结论。

所有会变化的外部结论在回答前重新查官方来源。检索结果带 URL 与查询日期；查不到时明确缺口。知识库召回结果必须先检查 `status`、`reviewed_at`、`valid_for` 和版本，再用于结论。

## 复核和失效

法规、制裁/出口管制、授权渠道、库存、价格、汇率和生命周期属于易变信息，不应在知识库中当作永久当前事实。为其指定资料 Owner 和复核期限；期限由企业合规/采购负责人结合风险确定。PCN/EOL 或监管变更出现时立即标记旧版 `superseded` 并链接替代资料。超过复核期限的资料自动视为 `needs_review`，只能作为历史线索，不能单独支持报价、采购或放行决定。

使用知识库的文件/目录整理权限和读取范围；客户 BOM、供应商报价、身份文件及合规材料按最小权限隔离。不要把无权共享的客户资料导入全局知识库。

## 最小评测集

建库后用至少以下问题做检索测试，并确认命中正确版本和来源：完整 MPN 与近似后缀的差异；旧版与当前 PCN/EOL；某市场当前授权查询入口；已过复核期的贸易规则；不同客户项目不可互相串用的 BOM/报价。故意加入过期资料作为负例，确认助手会指出已过期/范围不匹配，而不是照抄答案。更新模型、分块或资料版本后重跑这些问题。
